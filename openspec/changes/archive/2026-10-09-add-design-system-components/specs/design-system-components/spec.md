## ADDED Requirements

### Requirement: Набор UI-компонентов дизайн-системы
Система SHALL предоставлять переиспользуемые frontend-компоненты Stepper, Button style, Search input, Company buttons, Switch buttons, Speciality buttons, Grade select, Toggle with label, Chip, Chip input и Chip suggestion для дальнейшего функционала приложения.

#### Scenario: Все компоненты доступны для импорта
- **WHEN** разработчик реализует экран, которому нужны компоненты из нового набора
- **THEN** он MUST иметь возможность импортировать каждый компонент из `frontend/components/ui` или согласованного публичного UI export без обращения к Storybook-only коду

#### Scenario: Компоненты не требуют backend API
- **WHEN** компонент используется в Storybook или на frontend-экране
- **THEN** компонент MUST рендериться на основе переданных props без обязательного запроса к backend API

### Requirement: Компоненты используют MUI как базовый слой
Система SHALL реализовывать новые UI-компоненты поверх `@mui/material`, когда MUI предоставляет подходящий primitive для поведения, accessibility или состояния компонента.

#### Scenario: MUI primitive подходит компоненту
- **WHEN** компонент соответствует существующему MUI primitive, например Select, Switch, Chip, TextField, Stepper, ButtonBase, ToggleButton или Autocomplete
- **THEN** реализация MUST использовать этот MUI primitive или существующий проектный wrapper поверх него как основу компонента

#### Scenario: Макет требует кастомной геометрии
- **WHEN** Figma-макет требует визуальную форму, которую нельзя напрямую получить стандартными props MUI
- **THEN** реализация MUST сохранять MUI как поведенческую основу и дорабатывать внешний вид через theme, styled, sx или локальный wrapper


### Requirement: Figma-макеты являются источником истины
Система SHALL использовать Figma-фрейм `1970-5263` как обязательный источник истины для состава компонентов, вариантов, визуальных состояний, размеров, spacing, цветов и Storybook-примеров.

#### Scenario: Разработчик реализует компонент
- **WHEN** разработчик начинает реализацию любого компонента из набора
- **THEN** он MUST сверить компонент с соответствующим макетом и состояниями во Figma-фрейме `1970-5263`

#### Scenario: Storybook story готовится к проверке
- **WHEN** Storybook story для компонента считается готовой
- **THEN** story MUST отражать варианты и состояния, показанные в Figma-макете, если эти варианты и состояния присутствуют во фрейме

#### Scenario: Состояние отсутствует в Figma
- **WHEN** для компонента не указано отдельное состояние во Figma-фрейме `1970-5263`
- **THEN** разработчик MUST импровизировать это состояние согласно общему стилю текущей дизайн-системы, существующим MUI/theme-паттернам и визуальной логике макета
### Requirement: Button реализуется как расширение существующего AppButton
Система SHALL добавлять новый внешний вид кнопки как стиль, variant или prop существующего `AppButton` и MUI `MuiButton`, не создавая отдельный конкурирующий компонент Button.

#### Scenario: Требуется новый стиль кнопки из макета
- **WHEN** Figma-макет задает новый внешний вид кнопки
- **THEN** разработчик MUST расширить `AppButton` или theme variant `MuiButton`, сохранив совместимость с MUI `ButtonProps`

#### Scenario: Кнопка документируется в Storybook
- **WHEN** новый стиль кнопки реализован
- **THEN** `AppButton` Storybook story MUST показывать этот стиль вместе с основными состояниями, включая default, hover/active через визуальное описание или variants, и disabled

### Requirement: Кастомные цвета передаются hex-пропсами
Система SHALL принимать кастомные цвета компонентов только через явные props со значениями в hex-формате, если цвет должен быть динамическим.

#### Scenario: Компоненту передан динамический цвет
- **WHEN** компоненту нужен динамический цвет, например цвет компании, специальности, выбранного состояния или акцента
- **THEN** публичный API компонента MUST предоставлять семантически названный prop вроде `colorHex`, `backgroundHex`, `selectedColorHex` или `accentColorHex`

#### Scenario: Цвет не передан
- **WHEN** hex-проп цвета не передан
- **THEN** компонент MUST использовать дефолтный цвет из theme tokens или локального дефолта, согласованного с theme

#### Scenario: Передан невалидный цвет
- **WHEN** компонент получает цвет, который не соответствует hex-формату `#RGB`, `#RRGGBB` или `#RRGGBBAA`
- **THEN** компонент MUST не ломать рендер и MUST использовать безопасный дефолт или проигнорировать невалидное значение

### Requirement: Изображения передаются как URL
Система SHALL принимать изображения для компонентов через URL props, а не через обязательные локальные imports внутри компонента.

#### Scenario: Компонент отображает логотип или изображение
- **WHEN** company button, chip suggestion или другой компонент должен показать изображение
- **THEN** компонент MUST принимать URL строкой через prop вроде `imageUrl`, `logoUrl` или `iconUrl`

#### Scenario: URL изображения отсутствует
- **WHEN** изображение не передано и компонент допускает fallback
- **THEN** компонент MUST сохранять стабильный layout и показывать текстовый, цветовой или пустой fallback согласно API компонента

#### Scenario: Изображение передано
- **WHEN** компонент получает URL изображения
- **THEN** компонент MUST ограничивать размеры изображения и object-fit так, чтобы внешняя картинка не ломала layout

### Requirement: Интерактивные компоненты поддерживают управляемый выбор
Система SHALL предоставлять управляемый API для компонентов выбора, чтобы продуктовый код мог хранить состояние снаружи.

#### Scenario: Пользователь выбирает значение
- **WHEN** пользователь выбирает company button, switch button, speciality button, grade option, chip suggestion или step
- **THEN** компонент MUST вызвать documented callback с новым значением и не должен скрыто синхронизироваться с внешним состоянием без props

#### Scenario: Компонент получает selected value
- **WHEN** родительский код передает выбранное значение через prop
- **THEN** компонент MUST отобразить выбранное состояние в соответствии с переданным значением

### Requirement: Storybook документирует компоненты и состояния
Система SHALL иметь Storybook stories для каждого нового или расширенного компонента из набора.

#### Scenario: Разработчик открывает Storybook
- **WHEN** разработчик просматривает раздел UI в Storybook
- **THEN** он MUST видеть story для Stepper, AppButton с новым стилем, Search input, Company buttons, Switch buttons, Speciality buttons, Grade select, Toggle with label, Chip, Chip input и Chip suggestion

#### Scenario: Компонент имеет состояния
- **WHEN** компонент поддерживает состояния selected, disabled, error, empty, filled или interactive
- **THEN** Storybook story MUST показывать релевантные состояния через отдельные stories, args или композиционный пример

#### Scenario: Компонент поддерживает hex-цвета или URL-изображения
- **WHEN** компонент имеет props для hex-цветов или URL-изображений
- **THEN** Storybook story MUST включать пример использования этих props




### Requirement: SearchInput поддерживает адаптивную ширину и результаты поиска
Система SHALL предоставлять управляемый SearchInput без фиксированной ширины, чтобы потребитель мог задавать размеры через MUI sx, maxWidth, flex layout или родительский контейнер.

#### Scenario: Поле занимает ширину, заданную потребителем
- **WHEN** потребитель передает ограничения ширины или размещает SearchInput во flex-контейнере
- **THEN** компонент MUST соблюдать эти ограничения и не навязывать собственную фиксированную ширину

#### Scenario: Включена очистка значения
- **WHEN** SearchInput получает опциональный prop очистки и в поле есть текст
- **THEN** компонент MUST показать кнопку очистки и вызвать изменение управляемого значения после ее нажатия

#### Scenario: Переданы результаты поиска
- **WHEN** пользователь фокусирует SearchInput, а потребитель передал варианты результатов
- **THEN** компонент MUST показать доступный список результатов, поддержать выбор варианта и фильтрацию по введенному тексту

### Requirement: FieldInput поддерживает префикс и постфикс
Система SHALL предоставлять MUI-совместимый FieldInput с опциональным prefix image и строковым postfix.

#### Scenario: Переданы prefix image и postfix
- **WHEN** потребитель передает изображение префикса и непустой postfix
- **THEN** компонент MUST отобразить префикс, вертикальный разделитель высотой 16px и postfix в соответствии с макетом

#### Scenario: Используется числовой ввод
- **WHEN** FieldInput получает type="number"
- **THEN** компонент MUST сохранять числовой ввод и скрывать нативные spinner controls браузера

### Requirement: CityButtons поддерживает управляемый выбор города
Система SHALL предоставлять CityButtons на базе MUI ButtonBase с управляемым выбранным значением и настраиваемыми цветами элементов.

#### Scenario: Пользователь выбирает город
- **WHEN** пользователь нажимает доступную кнопку города
- **THEN** компонент MUST вызвать onChange с value города и показать selected-состояние согласно переданному value

### Requirement: ChipInput поддерживает active search и нативную прокрутку
Система SHALL предоставлять единый управляемый ChipInput, в котором выбранные чипы, активный поиск и список результатов синхронизированы между собой.

#### Scenario: Выбранные чипы переполняют область
- **WHEN** высота списка выбранных чипов превышает макетную видимую область
- **THEN** компонент MUST ограничить область, показать стилизованный нативный scrollbar браузера без кастомных кнопок и оставить доступными колесо, тачпад и клавиатурную прокрутку

#### Scenario: Active search содержит много результатов
- **WHEN** active search открывает список результатов, превышающий его видимую высоту
- **THEN** список MUST использовать тот же стилизованный нативный scrollbar браузера

#### Scenario: Выбор синхронизирован в обоих направлениях
- **WHEN** пользователь выбирает или снимает вариант в нижнем списке
- **THEN** соответствующий chip сверху MUST добавляться или удаляться

#### Scenario: Пользователь удаляет выбранный chip
- **WHEN** пользователь удаляет chip из верхней области
- **THEN** соответствующий вариант в списке результатов MUST потерять selected-state

#### Scenario: Active search теряет фокус
- **WHEN** фокус уходит за пределы ChipInput
- **THEN** нижний список результатов MUST скрыться, а верхний контейнер MUST восстановить одинаковое скругление сверху и снизу
