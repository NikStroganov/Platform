## Why

В проекте нужен согласованный набор переиспользуемых UI-компонентов, чтобы дальше собирать функциональность быстрее и без расхождений с макетами. Компоненты должны быть реализованы по фрейму Figma и задокументированы в Storybook, чтобы их можно было проверять, переиспользовать и развивать как часть дизайн-системы.

## What Changes

- Добавить UI-компоненты по макетам из Figma-фрейма `1970-5263`: Stepper, Button, Search input, Field input, Company buttons, Switch buttons, Speciality buttons, City buttons, Grade select, Toggle with label, Chip, Chip input, Chip suggestion.
- Использовать Figma-макеты как обязательный источник истины для состава компонентов, визуальных состояний, размеров, spacing, цветов и контента Storybook-примеров.
- Для каждого компонента подготовить Storybook-документацию с основными состояниями и вариантами, необходимыми для дальнейшей разработки.
- Зафиксировать, что OpenSpec-документы для этого change ведутся на русском языке, если пользователь не попросит изменить язык.
- Не добавлять breaking changes.

- Расширить SearchInput адаптивной шириной, очисткой значения и результатами поиска.
- Зафиксировать единый ChipInput active/overflow с нативными стилизованными scrollbar и синхронизацией chips с результатами поиска.

## Capabilities

### New Capabilities

- `design-system-components`: Набор базовых UI-компонентов и их Storybook-документация для дальнейшего функционала приложения.

### Modified Capabilities

- Нет.

## Impact

- Затрагивает frontend UI-компоненты, Storybook stories и связанные с ними типы/стили.
- Требует обязательной сверки с Figma-макетами перед реализацией компонентов и при финальной проверке Storybook.
- Может потребовать переиспользования или расширения существующих компонентов дизайн-системы, если они уже есть в проекте.
