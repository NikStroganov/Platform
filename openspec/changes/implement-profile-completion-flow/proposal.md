## Why

После авторизации пользователю нужен цельный процесс заполнения профиля, чтобы приложение могло собрать анонимные рабочие данные и отправить их в onboarding API без разрозненных временных экранов. Сейчас уже есть набор профильных UI-компонентов из change `add-design-system-components`, сгенерированный API-клиент и Figma-флоу `2031:5312`, поэтому можно зафиксировать контракт флоу и начать реализацию с общего шаблона и механизма шагов.

## What Changes

- Добавить frontend-флоу заполнения профиля по Figma node `2031:5312` из файла `Startup-Team`.
- На первом этапе реализации создать общий экранный шаблон флоу: логотип, прогресс/stepper, центральная область шага, нижняя основная кнопка, навигация и механизм переключения шагов.
- Использовать компоненты из существующей capability `design-system-components`, включая `AppStepper`, `AppButton`, `FieldInput`, `GradeSelect`, `SwitchButtons`, `CompanyButtons`, `CityButtons`, `SpecialityButtons`, `ToggleWithLabel`, `ChipInput` и связанные shared-компоненты.
- Использовать сгенерированный API-клиент из `frontend/lib/api/gen` и существующий wrapper `frontend/lib/api/client.ts`; финальная отправка данных должна идти через `api.saveOnboarding`.
- Реализовывать конкретные шаги флоу поэтапно по отдельным макетам, сохраняя общий state-механизм и DTO-маппинг для всего процесса.
- Не добавлять breaking changes.

## Capabilities

### New Capabilities

- `profile-completion-flow`: Многошаговый frontend-флоу заполнения профиля с общим шаблоном экрана, управляемым переключением шагов, накоплением данных onboarding-формы и отправкой через сгенерированный API-клиент.

### Modified Capabilities

- Нет.

## Impact

- Затрагивает frontend application routing/pages, feature-модуль профиля/onboarding, общий state флоу, UI-композицию и API-вызов `saveOnboarding`.
- Опирается на существующую capability `design-system-components`; новые базовые UI-компоненты в рамках этого change не планируются, но возможна точечная адаптация композиции под экранные сценарии.
- Требует сверки каждого шага с Figma node `2031:5312`; начальная реализация должна обеспечить общий шаблон и навигацию, а последующие задачи будут наполнять шаги отдельными экранами.
- Использует типы `OnboardingDto`, каталожные методы, smart search и top-list endpoints из сгенерированного API там, где шагу нужны backend-данные.
